# 블라인드 선정·갱신 프로토콜

## 1. 문제 정의

목표는 특정 환자의 정답률을 올리는 답안표가 아니라, 새로운 CPX 증례에서도 작동하는 기전 중심 지식층을 만드는 것이다.

## 2. 단계 분리

### A. 범위 선정

입력은 주호소 이름의 집계와 일반 CPX 범주만 허용한다. 증례 ID, 진단명, 환자 대본, 모범답안, 채점표는 보지 않는다.

각 주호소는 아래 다섯 기준을 0~2점으로 평가한다.

| 기준 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 재사용성 | 한 질환에 국한 | 한 계통에서 반복 | 여러 계통·질환에서 반복 |
| 기전 다양성 | 단일 기전 | 2개 기전군 | 3개 이상 기전군 |
| 문진 분별력 | 낮음 | 일부 분별 | 양상·시간·동반증상으로 분별 |
| 진찰 분별력 | 낮음 | 보조적 | 진찰 결과가 기전 분기에 직접 연결 |
| 안전 중요도 | 낮음 | 지연 시 불리 | 즉시 배제할 위험 분기 존재 |

총 7점 이상을 1차 지식팩에 포함한다. 특정 증례의 출제 빈도만으로 질환을 추가하지 않는다.

### B. 지식 작성

각 주호소에 대해 다음 순서로 작성한다.

1. 주호소의 표준 개념과 환자 표현을 정규화한다.
2. 질환명이 아니라 병태생리 기전군을 먼저 나눈다.
3. 각 기전군이 만드는 증상·징후를 연결한다.
4. 기전군을 구분할 문진 차원을 정한다.
5. 수행 가능한 신체진찰 행동을 표준 진찰 카탈로그에 연결한다.
6. 즉시 평가가 필요한 안전 신호를 별도 표시한다.
7. 모든 연결에 외부 근거 출처를 붙인다.

### C. 검증

내용 검증 전에 JSON 스키마와 참조 무결성을 검사한다.

- 모든 ID는 `snake_case`
- source/exam 참조가 존재
- 주호소 검색 별칭이 서로 충돌하지 않음
- 기전마다 증상 또는 징후가 하나 이상 있음
- 기전마다 질문 또는 진찰 연결이 하나 이상 있음
- 환자 표현에 검사 결과나 확정 진단을 넣지 않음

### D. 홀드아웃 연결성 검사

지식팩을 동결하고 해시를 기록한 뒤에만 기존 DB와 연결성을 검사한다.

허용:

- 주호소 문자열이 어느 표준 개념으로 매칭되는지
- 기존 진찰 이름이 어느 표준 진찰 행동으로 매칭되는지
- 매칭 실패율과 중복 매칭률

금지:

- 정답 진단을 본 뒤 기전 추가
- 체크리스트를 본 뒤 질문 항목 추가
- 점수가 낮은 증례에만 유리한 표현 추가

매칭 실패는 표현 정규화 사전의 문제로 처리하고, 의학 내용 변경과 분리한다.

## 3. 버전 관리

- 의학 내용 변경: minor 버전 증가 (`v1.1`)
- ID·스키마 변경: major 버전 증가 (`v2`)
- 별칭만 추가: patch 버전 증가 (`v1.0.1`)
- 모든 변경은 근거 출처와 변경 이유를 남긴다.

## 4. 평가 원칙

이 DB의 성능은 특정 증례 정답률 하나로 평가하지 않는다.

- 새로운 주호소에서 적절한 기전 후보를 제시하는가
- 질문과 진찰이 실제로 기전군을 구분하는가
- 위험 신호를 놓치지 않는가
- 불필요한 질문·진찰을 늘리지 않는가
- 같은 의미의 표현이 안정적으로 정규화되는가
- SOAP에 확인하지 않은 사실을 넣지 않는가
