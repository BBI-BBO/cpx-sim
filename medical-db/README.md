# CPX Core Medical Knowledge Base

이 디렉터리는 특정 증례의 정답을 맞히기 위한 답안집이 아니라, 여러 CPX 증례에 재사용할 수 있는 **주호소 중심 의학 지식 그래프**다.

## 목적

다음 연결을 명시적으로 저장한다.

```text
병태생리 기전 → 환자가 느끼는 증상·관찰되는 징후 → 주호소
                                   └→ 확인할 문진·신체진찰
```

이 구조는 Doctor Agent가 증례명을 먼저 맞히는 대신, 환자의 주호소에서 가능한 기전군을 세우고 질문과 진찰로 구분하도록 돕는다.

## 과적합 방지 원칙

지식팩을 만들 때 허용하는 입력:

- 일반적인 CPX/OSCE 고빈도 주호소 목록
- 주호소 이름만 있는 집계 자료
- 공개 교과서·전문학회·공공기관의 임상 자료
- 해부·생리·병태생리의 일반 원칙

금지하는 입력:

- 현재 CPX 증례의 `truth`
- 환자 대본, 모범 답안, 체크리스트, red flag 정답
- 제출 기록과 점수 피드백을 보고 역으로 만든 문구
- 공개 샘플의 증례별 정답에만 맞는 검사·진찰 조합

선정 규칙은 콘텐츠를 쓰기 전에 고정한다.

1. 여러 장기계통에서 반복되는 주호소인가
2. 서로 다른 기전군이 같은 주호소를 만들 수 있는가
3. 문진과 신체진찰로 기전군을 구분할 수 있는가
4. 놓치면 위험한 분기가 있는가
5. 한 증례가 아니라 여러 증례에 재사용 가능한가

위 기준으로 1차 범위를 정했다.

- 복통
- 복부팽만
- 발열
- 황달
- 흉통
- 호흡곤란
- 두근거림
- 부종
- 비의도적 체중감소
- 불면
- 저신장

이 목록은 특정 증례의 진단명을 보지 않고 고정한 버전 `cpx-core-v1`이다. 배포 후 증례와의 연결률은 **정답을 보지 않고** 주호소·진찰 용어의 문자열 매칭만으로 측정한다. 내용 수정은 독립 근거가 있을 때만 다음 버전으로 올린다.

## 정규화 규칙

모든 개념은 안정적인 영문 `snake_case` ID와 한국어 표준 표기를 가진다.

- 유니코드는 NFC로 정규화한다.
- 영문은 소문자로 바꾼다.
- 앞뒤 공백을 제거하고 연속 공백을 하나로 줄인다.
- 검색 키에서는 공백·마침표·가운뎃점·하이픈을 제거한다.
- 환자 표현과 의학 용어를 같은 문자열로 덮어쓰지 않고 `aliases`로 연결한다.
- 주관적 증상과 객관적 징후를 구분한다.
  - `가슴이 두근거림`은 증상이다.
  - `빈맥`은 활력징후 또는 진찰 소견이다.
  - `눈이 노래 보임`은 환자 관찰이다.
  - `공막 황달`은 진찰 소견이다.
- 하나의 표현이 여러 개념에 걸릴 수 있으면 더 넓은 상위 개념으로 자동 확정하지 않고 후보를 함께 반환한다.
- 진찰은 결과가 아니라 **행동**을 표준화한다. 예: `복부 촉진`과 `반발통 확인`은 별도 행동이다.

## 파일

- `cpx_core_v1.json`: 주호소·기전·증상·진찰·출처 원본
- `SELECTION_PROTOCOL.md`: 블라인드 선정·갱신 절차
- `../scripts/validate_medical_kb.py`: 정규화 충돌과 참조 무결성 검사
- `../scripts/render_medical_kb_sql.py`: JSON을 배포용 SQL로 변환
- `../supabase/schema.sql`: 실제 DB 테이블 정의

## 데이터 사용 경계

이 DB는 질문·진찰 후보를 제시하는 일반 지식이다. 다음 용도로 사용하지 않는다.

- 현재 증례의 숨은 진단을 직접 반환
- 환자 대본에 없는 증상을 있다고 가정
- 시행하지 않은 진찰 결과를 생성
- SOAP에 묻지 않은 사실을 자동 삽입
- 로컬 채점기의 정답·체크리스트를 노출

Doctor Agent는 DB가 제안한 항목도 실제로 질문하거나 진찰한 뒤에만 SOAP에 기록한다.

## 근거 출처

1차 버전은 NCBI Bookshelf의 *Clinical Methods*, MSD Manual Professional Edition, 공개 임상지침을 중심으로 작성했다. 원문 문장을 복사하지 않고 기전·임상 연결을 한국어로 재서술했다. 각 프로필과 진찰 항목은 `source_ids`로 근거를 추적한다.
